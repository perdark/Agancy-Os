# Discovery Stage — Design Spec

**Date:** 2026-07-08
**Status:** Approved for planning
**Scope:** First real, AI-powered stage of Agency OS. Local-only.

## Goal

Turn the Genesis flow into a working **Discovery** stage: the operator enters a
messy brief plus the client's actual words, and Claude decodes it into
structured decisions — including the questions the operator should ask the
client — all wrapped in the mandatory Stage Contract.

This is the "vague-feedback translator" that is the soul of Agency OS. It is the
first thing the owner would actually open on a real client, which is why it,
not a by-hand form, is the first slice.

## Decision log (why this slice, this way)

- **Override the "no AI in V1" rule, for Discovery only.** The product's value is
  AI translating vague feedback. A by-hand version proves nothing and would not
  be used. Owner confirmed.
- **Use the seam the foundation already designed.** The `GenesisGenerator` port +
  `PlaceholderGenesisGenerator` fallback exist precisely so a real generator can
  be swapped in via composition. We are filling that seam, not bending the
  architecture.
- **Fix the stage-mapping bug.** Genesis currently records its result under the
  `"brand"` stage and leaves `currentStage: "discovery"` empty. Discovery must
  record under `"discovery"`.
- **Local, direct Anthropic.** No Vercel Gateway. `@ai-sdk/anthropic` +
  `ANTHROPIC_API_KEY` in `.env.local`. Model `claude-sonnet-5`.

## In scope

1. Discovery output shape + domain rename (Genesis-the-output → Discovery).
2. Real `ClaudeDiscoveryGenerator` implementing the generator port.
3. Placeholder kept as the no-API-key fallback.
4. Composition binding (key present → Claude; absent → placeholder).
5. Discovery result recorded under `"discovery"`.
6. Output UI: decoded signals + open questions + assumptions + Stage Contract.
7. First domain tests (Vitest) — we currently have none.

## Out of scope (explicitly not now)

Editing the contract by hand · other stages (Brand…Development stay
placeholders) · deploy · auth · storage/DB · Arabic UI polish · streaming ·
retries/queues · cost tracking.

## Naming decisions

The **Genesis flow** (create a project from a brief) keeps its name — it is the
birth of a project. The **Discovery stage** is what that flow runs.

| Symbol | Change |
| --- | --- |
| `features/genesis/*`, route `/projects/new` | keep |
| `GenesisInput` (the brief) | keep |
| `GenesisOutput` | replace with `DiscoveryOutput` (new fields) |
| `GenesisGenerator` (port) | rename → `DiscoveryGenerator` |
| `PlaceholderGenesisGenerator` | rename → `PlaceholderDiscoveryGenerator` |
| new | `ClaudeDiscoveryGenerator` |
| stage recorded | `"brand"` → `"discovery"` |

## Discovery output shape

`DiscoveryOutput` is the `TOutput` of the Discovery `StageResult`.

```ts
interface DiscoveryOutput {
  /** A clean restatement of what the client actually seems to want. */
  readonly interpretedBrief: string;
  /** The core move: decode vague client words into likely meaning. */
  readonly decodedSignals: readonly DecodedSignal[];
  /** Questions the operator should ask the client — generated by the AI. */
  readonly openQuestions: readonly OpenQuestion[];
  /** What the AI is assuming, stated so the operator can correct it. */
  readonly assumptions: readonly string[];
}

interface DecodedSignal {
  readonly clientSaid: string;   // e.g. "make it premium"
  readonly likelyMeans: string;  // interpretation
  readonly confidence: "low" | "medium" | "high";
}

interface OpenQuestion {
  readonly question: string;
  readonly whyItMatters: string;
}
```

Wrapped by the existing Stage Contract:
- **readiness** = Brief Clarity (0–100): how clearly the brief defines the work.
- **doubts / missingInformation / recommendations / nextStep** as defined by the
  contract. The quality gate is *derived* from readiness by `buildStageResult` —
  the generator never sets the gate directly.

## Architecture & data flow

```
/projects/new (genesis-form, existing)
   → server action createProjectFromGenesis (re-validate with Zod)
   → runGenesis use-case (service.ts)
        1. createProject(identity)
        2. attach assets
        3. discoveryGenerator.generate(input, context)   ← PORT
        4. recordStageResult(workflow, result)  // stage: "discovery"
        5. withHistory(stage.run, "discovery")
        6. projects.save(project)
   → redirect to /projects/[id]  → renders Stage Contract + DiscoveryOutput
```

**`ClaudeDiscoveryGenerator` (lib/ai/):**
- Builds the prompt from `prompts/discovery/discovery.prompt.ts` (versioned).
- Calls the AI SDK `generateObject` with a Zod schema mirroring
  `DiscoveryOutput` **plus** the contract signals Claude authors: `readiness`
  (0–100), `doubts[]`, `missingInformation[]`, `recommendations[]`, `nextStep`.
- Maps the model object into a `StageResult` via `buildStageResult`, injecting
  ids from `context.ids` and `producedAt` from `context.clock`. Content comes
  from Claude; structure, ids, time, and the derived gate stay deterministic.
- `stage: "discovery"`.

**Prompt persona:** a senior agency strategist working with clients (often in
Iraq) who cannot articulate what they want; job is to decode vague words, name
assumptions, and produce the questions that would raise brief clarity.

## Composition

`getContainer()` binds `discoveryGenerator`:
- `process.env.ANTHROPIC_API_KEY` present → `ClaudeDiscoveryGenerator`.
- absent → `PlaceholderDiscoveryGenerator` (app still runs with zero setup).

## Error handling

The Claude call is wrapped in try/catch inside `ClaudeDiscoveryGenerator`. On
API/parse failure it throws a typed `DiscoveryGenerationError`. `runGenesis`
lets it propagate; the server action catches it and returns
`{ ok: false, error }`, which the form surfaces. We do **not** silently fake a
result — a failed decode is honest and visible. (No project is persisted on
failure.)

## UI

- `features/genesis/components/genesis-output-view.tsx` → render
  `DiscoveryOutput`: decoded signals as a table (said → means → confidence),
  open questions as a list with "why it matters", assumptions as a list.
- Existing `StageContractView` renders the wrapper unchanged.
- Project detail page reads `project.workflow.results.discovery` (was `.brand`).

## Testing (Vitest — new)

Add `vitest` + a `test` script. First focused tests:
1. `readinessScore` clamps to 0–100 and rounds.
2. `evaluateQualityGate` boundaries (74→fail, 75→pass, 50→warning).
3. `StageRegistry` rejects duplicate `register`; `ordered()` sorts by order.
4. `recordStageResult` / `stageStatus` transitions (discovery current→done).
5. `PlaceholderDiscoveryGenerator` returns a valid `StageResult` with
   `stage: "discovery"` and a derived gate consistent with its readiness.
6. `buildStageResult` derives the gate from readiness (content-agnostic).

The `ClaudeDiscoveryGenerator`'s network call is **not** unit-tested (no live
model in tests); its mapping logic is covered via a fake model object if cheaply
possible, otherwise verified by running the app.

## Verification (definition of done)

- `npx tsc --noEmit` clean, `eslint` clean, `vitest` green.
- With no key: create a project → Discovery placeholder renders, recorded under
  `"discovery"`, timeline shows Discovery done.
- With a real key in `.env.local`: create a project from a genuinely vague brief
  → decoded signals, open questions, and a Brief Clarity score render; doubts and
  missing info are non-trivial. Confirmed by actually running it (`/run`).
